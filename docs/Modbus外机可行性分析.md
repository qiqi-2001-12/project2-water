# Modbus RTU 外机接入可行性分析

## 1. 结论

**可以实现，且可以与现有自定义协议设备同时兼容。** 推荐采用“主控板/协议网关桥接”的方式：App 继续使用现有的自定义协议和 `115200` 串口，主控板（或专用协议网关）使用独立的 RS485 口以 `9600` 与 Modbus RTU 外机通讯。

> 现场表述中的“11520”需要复核。当前工程的 `SerialHelper` 默认实际配置为 `/dev/ttyAS3`、`115200`、8 数据位、无校验、1 停止位（8N1），见 `app/src/main/java/android/serialport/SerialHelper.java`。下文按 115200 分析。

| 方案 | 可行性 | 是否需要主控/网关固件 | 适用条件 | 建议 |
| --- | --- | --- | --- | --- |
| A. 主控板/网关协议桥接 | 高 | 需要 | App 当前只有一条自定义协议链路；可修改主控或另加网关 | **推荐** |
| B. Android 独立物理串口直连 Modbus | 高 | 不需要（但要改 App） | 终端存在未占用、可访问的第二个 UART/RS485 口 | 备选 |
| C. 同一 UART 在 115200 与 9600 间切换 | 低 | 不适合 | 仅一条物理串口，且原设备必须持续在线 | 不推荐 |
| D. 纯“波特率转换器” | 不成立 | 不适用 | 转换器只改变速率/电平 | 不可作为协议接入方案 |
| E. 协议转换网关 | 高 | 网关需配置/开发 | 网关可把自定义报文真正映射为 Modbus 请求和响应 | 可作为 A 的硬件替代 |

## 2. 已核对的工程现状

1. `HyApplication` 启动时调用 `SpDataProcessor.getInstance().init()`，全局只打开了一条 App 串口。
2. 串口为 `/dev/ttyAS3`，代码默认波特率为 `115200`；当前收包器仅查找 `AA 55` 报文头，按自定义长度字段取帧，并校验自定义 CRC。
3. 自定义上行/下行帧带有设备类型（`termType`）、功能号和请求序号。`SpDataProcessor` 按设备类型把状态分发为 `OutDoorStatusInfo`、`PVStatusInfo`、`UpTempStatusInfo` 等 EventBus 事件。
4. 首页实际使用的是 `ManagerFragment`，管理员页面布局是 `app/src/main/res/layout/manager_main.xml`；已有密码遮罩，因此可在该页面受控地增加“Modbus 外机”入口。
5. 工程中已有 Modbus CRC16（多项式 `0xA001`）计算工具，但不存在 Modbus RTU 帧组包、按静默时间切帧、异常帧处理、寄存器映射或独立 Modbus 串口调度实现。

因此，不能把 Modbus 原始报文直接交给现有 `SpDataProcessor`，也不能将现有自定义帧直接发给 Modbus 外机。

### 2.1 已收到的水机寄存器地址表（2026-09-17）

已核对来源文件 `D:\桌面\水机新增协议表.xlsx`。该文件是本次水机外机的**业务寄存器地址表**，可作为 UI 字段及网关映射的依据：

- `设置参数`：169 项，地址为 `1001–1129`（P01–P129）和 `1400–1439`（P130–P169），表中同时给出了多数参数的默认值、最小值和最大值。例如：`1001/P01` 制热设定温度、`1002/P02` 制冷设定温度、`1102/P102` Modbus 地址（合法范围 1–99）。
- `状态信息`：66 项业务点。模拟量/状态点 `2121/B01` 至 `2150/B30`，开关量 `2151/D01` 至 `2162/D12`，输出/执行量 `2170/Y00` 至 `2193/Y23`（中间保留 `2163–2169`）。例如 `2121/B01` 进水温度、`2122/B02` 出水温度、`2130/B10` 排气温度、`2143/B23` 驱动运行状态、`2183/Y13` 当前流量。

### 2.2 已确认的 Modbus RTU 通讯定义（2026-09-17）

外机资料已明确：

| 项目 | 确认值 | 实现含义 |
| --- | --- | --- |
| 协议 | 标准 Modbus RTU | 使用标准 RTU CRC16，在线路中 CRC 低字节先发送 |
| 串口 | `9600 / 8N1` | 8 数据位、无奇偶校验、1 停止位；与 App 现有 `/dev/ttyAS3` 的 `115200/8N1` 不能直接共用同一个 UART |
| 角色 | 水机主控板为从机；线控器为主机 | 若 App/网关直接接水机，它必须作为唯一 Modbus 主机；不能与线控器同时主动发起请求 |
| 设置参数区 | `900–1699`，可读写 | `03H` 读保持寄存器，`06H` 写单寄存器，`10H` 写多个寄存器 |
| 状态参数区 | `2000–2199`，只读 | `04H` 读输入寄存器 |

因此，Excel 中 `P01=1001` 等设置项归入 `03H/06H/10H` 路径；`B01=2121`、`D01=2151`、`Y00=2170` 等状态项归入 `04H` 路径。读取状态时可按连续区间分成 `2121–2150`、`2151–2162`、`2170–2193` 三次 `04H` 请求，避免依赖保留地址的返回行为。

仍需确认但已收敛为以下三项：

1. 地址的基准：表内 `1001` 是否发送为 PDU 地址 `1000 (0x03E8)`，还是设备要求直接发送 `1001`。标准 Modbus 文档常见 1 基显示地址和 0 基 PDU 地址差一，必须以厂家十六进制请求样例验证。
2. 每个点的寄存器数量、无符号/有符号/浮点类型、字节序/字序和缩放比例。特别是温度、压力、频率以及 `Y13`（表中仅标注“L/min，保留一位小数”）不能假定为整数或固定除以 10。
3. 水机主控板的当前**从站地址**。资料中的“线控器为主机，默认地址为 1”不能直接替代从站地址：标准 Modbus RTU 的单播请求第一个字节是从站地址，主机本身通常不使用该地址。Excel 的 `P102=1102` 是可配置 Modbus 地址项（范围 1–99），需确认它是否正是水机主控板的从站地址及当前实际值。

这份表和已确认的通讯定义使“状态展示”和“受限参数设置”的业务范围已经清楚；在取得上述三项及一组真实请求/响应十六进制样例后，即可进入真实设备联调。

## 3. “9600 转 115200/11520”的判断

RS485 是物理层，`9600`/`115200` 是串口速率，自定义协议和 Modbus RTU 是报文协议；三者是不同层次。

```text
仅波特率转换器：       9600 Modbus 原始字节 <----> 115200 Modbus 原始字节
                                                   ↑ 仍然是 Modbus，不会变成 AA 55 帧

协议转换网关/主控： App 自定义帧 <-> 解析/映射 <-> 9600 Modbus RTU 帧 <-> 外机
```

所以：

- **只有波特率转换功能的设备不能使用。** 它不会补报文头、不会计算/交换协议 CRC、不会把“设置参数”映射为 Modbus 写寄存器，也不会把读寄存器结果封装为 App 需要的状态帧。
- 若该设备的说明书明确写有“协议转换”“Modbus RTU slave/master gateway”“可配置命令映射/寄存器映射”，它不是普通波特率转换器，可以评估使用；必须用抓包验证输入输出字节已发生协议映射。
- 若原自定义设备和 Modbus 外机挂在**同一条 RS485 总线**，但速率不同，普通总线不能同时稳定工作。应让主控使用两路 UART/两路 RS485，或由双口网关分别接入。不能把一个 RS485 口配置成两个波特率同时通信。
- 即使所有设备改成相同波特率，也仍然需要协议解析和总线主站调度；同一总线上的 Modbus 外机只能由一个 Modbus 主站轮询，不能让多个主站同时发问。

## 4. 推荐拓扑：主控/网关协议桥接

```text
管理员 UI
    │ EventBus / Repository
    ▼
App: SpDataProcessor（/dev/ttyAS3，115200，自定义 AA 55 帧）
    │
    ▼
主控板或协议网关
  - 解析新增的外机设备类型/功能号
  - 请求队列、超时和重试
  - 自定义状态帧回包
    │ RS485-A/B，9600，实际串口参数以外机手册为准
    ▼
Modbus RTU 外机（唯一从站地址）
```

### 优点

- 不破坏已经实际运行的 App—主控自定义协议链路和现有页面。
- App 仍只有一条串口、一个发送队列，不会出现同口抢占、切速率和混帧风险。
- Modbus 的超时重试、总线仲裁、离线状态由靠近设备的一侧统一处理，便于现场维护。
- 将来增加第二台 Modbus 外机，只增加从站地址和寄存器表，不必复制 App 串口基础设施。

### 代价及前提

- 需要能修改主控板固件，或采购/开发有双串口且支持自定义协议映射的网关。
- 必须取得外机完整 Modbus RTU 通讯说明书；只有“9600”不足以开发。
- 若 App 的设置还要同步至云端，需要确认 MQTT 上报/下发的字段定义并增加兼容字段。

## 5. 备选拓扑：App 直接接第二物理串口

```text
App /dev/ttyAS3（115200，自定义协议） -> 原主控
App /dev/ttyXXX（9600，Modbus RTU）   -> 独立 RS485 收发器 -> Modbus 外机
```

该方案仅在 Android 硬件确认有第二个空闲 UART、内核节点可访问、且 RS485 收发方向由硬件/驱动正确控制时采用。实现时应新增独立的 `ModbusRtuTransport`，绝不能在 `SpDataProcessor` 中把现有串口关闭、改为 9600、通信后再改回 115200。

直接接入的额外风险：Android 端要处理 RS485 方向控制、响应帧分段/粘包、3.5 字符时间的 RTU 帧边界、并发请求串行化、离线恢复和现场电气问题。若没有第二物理口，不能以软件方式解决。

## 6. 开工前必须冻结的外机协议资料

必须由外机厂家/现场联调人员提供并以报文样例验收：

1. Modbus 模式：RTU（不是 ASCII/TCP）；波特率、数据位、校验位、停止位，例如 9600/8N1 或 9600/8E1。
2. 从站地址范围及本设备出厂/现场地址；是否可在软件中改地址。
3. 寄存器表：功能码、寄存器地址（明确文档地址是 0 基还是 1 基）、读写权限、寄存器数量、数据类型、字节序/字序、比例系数、单位、有效范围和保留值。
4. 状态、告警、故障码、运行模式、启停、目标值等每个 UI 项的准确映射；写入是否要求解锁、密码或写后保存。
5. 每条命令的请求/正常响应/异常响应十六进制样例；响应超时、最小命令间隔、允许重试次数。
6. RS485 接线图：A/B 命名、信号地、终端 120Ω、电源隔离、总线长度和节点数量；不同厂家的 A/B 命名可能相反，必须现场验证。

## 7. 风险与验收门槛

| 风险 | 后果 | 控制措施 |
| --- | --- | --- |
| 把波特率转换误认为协议转换 | 完全无法通讯 | 要求网关给出转换前后抓包和命令映射表 |
| 使用错误串口参数/校验位 | CRC 或超时失败 | 以外机手册和 USB-RS485 抓包确认；不可只依据 9600 |
| 寄存器地址基准错一位 | 读错数据或误写参数 | 在配置中统一保存 0 基 PDU 地址，文档明确换算 |
| 16/32 位字序或比例未知 | 温度、频率等显示/写入错误 | 每种数据用实测值和厂家样例做单元测试 |
| 多主站或混速率共用一条 485 | 随机冲突、设备离线 | 每段总线只保留一个主站、一个速率；采用双口隔离 |
| 写参数失败/误写 | 外机异常运行 | 管理员权限、二次确认、范围校验、写后回读、审计日志 |
| 轮询过快 | 总线拥塞、UI 假离线 | 单请求在途，超时后再下一个；默认 2–5 秒轮询，可配置 |

最低验收标准：连续 24 小时轮询无协议解析异常；断线、CRC 错误、Modbus 异常码可在 UI 明确展示；每个可写参数均能范围拦截、写后回读一致；原有自定义外机功能回归通过。
